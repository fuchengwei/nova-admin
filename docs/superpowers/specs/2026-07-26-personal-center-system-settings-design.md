# 个人中心与系统设置页设计文档

> 日期：2026-07-26  
> 状态：已获对话内设计确认，待用户审阅书面规格  
> 范围：个人中心、头像上传、平台级系统设置  
> 项目：Nova Admin

## 1. 背景与目标

Nova Admin 已具备 RBAC、用户、角色、菜单、字典、日志、文件、任务、监控等后台基础能力，但当前 Header 中的“个人中心”入口尚未落地，系统设置也缺少统一配置页面。此次设计目标是补齐两类常见中后台能力：

1. 登录用户可以在个人中心查看并维护自己的资料、头像和密码。
2. 管理员可以在系统设置页维护基础设置、安全策略、上传策略和通知公告配置。
3. 新增能力遵循现有 Spring Boot + React + Ant Design ProComponents 架构、RBAC 权限模型、统一响应格式、i18n 和测试规范。

## 2. 范围

### 2.1 包含

- 个人中心页面 `/profile`。
- Header 用户菜单“个人中心”跳转。
- 当前用户资料查看与编辑。
- 当前用户头像上传。
- 当前用户修改密码。
- 当前用户账号安全信息展示。
- 系统设置页面 `/system/settings`。
- 系统设置四个分组：基础设置、安全策略、上传策略、通知公告。
- 后端系统配置持久化模型与按组读写接口。
- 菜单、权限、初始化配置数据。
- 关键后端与前端测试。

### 2.2 不包含

- 任意 key-value 配置项管理表格。
- 邮件、短信真实发送通道接入。
- 多租户级配置隔离。
- 用户个人偏好与系统默认设置的完整合并策略。
- 外部对象存储新接入；头像上传复用现有文件服务能力。

## 3. 方案选择

采用“平台配置骨架 + 核心配置落地”的方案。

该方案会实现完整的平台配置中心结构，并让第一版配置在关键场景生效：基础展示配置供前端展示读取；上传策略用于头像上传；密码策略用于个人修改密码和用户重置密码校验；通知公告配置可保存并供后续展示或发布能力扩展。邮件/短信等外部通道第一版仅保存配置和状态，不引入新第三方依赖。

选择原因：它满足平台配置版方向，同时避免一次性引入过多外部集成和认证链路变更，便于测试和迭代。

## 4. 信息架构与页面功能

### 4.1 个人中心 `/profile`

入口：Header 用户下拉菜单中的“个人中心”。该页面是登录用户通用页面，不依赖后端菜单展示权限。

页面分区：

1. 用户概览卡片
   - 头像、昵称、账号、部门、角色。
   - 最近登录时间、最近登录 IP。
2. 基本资料
   - 可编辑字段：昵称、真实姓名、邮箱、手机号、性别。
   - 只读字段：账号、部门、角色、状态。
3. 头像上传
   - 支持选择图片并上传。
   - 上传成功后更新 `sys_user.avatar`。
   - 前端同步刷新页面头像和 Header 头像。
   - 后端按上传策略校验头像大小和类型。
4. 修改密码
   - 字段：旧密码、新密码、确认密码。
   - 后端校验旧密码和密码策略。
   - 修改成功后前端清理 token 并跳转登录页，要求重新登录。
5. 账号安全信息
   - 展示最近登录时间、最近登录 IP、角色、权限数量等只读信息。

### 4.2 系统设置 `/system/settings`

入口：作为“系统管理”下的新菜单，由后端菜单数据控制展示。

权限：

- 查看：`system:settings:view`
- 编辑：`system:settings:edit`

页面使用 Tab 分组，每个 Tab 独立读取和保存。

1. 基础设置
   - 系统名称。
   - 浏览器标题。
   - Logo URL。
   - 默认语言。
   - 主题色。
   - 版权文本。
2. 安全策略
   - 密码最小长度。
   - 是否要求数字、字母、特殊字符。
   - 登录失败锁定次数。
   - 锁定分钟数。
   - 验证码开关。
   - Access Token 和 Refresh Token 过期时间配置。
3. 上传策略
   - 通用最大上传大小。
   - 通用允许文件类型。
   - 头像最大上传大小。
   - 头像允许文件类型。
4. 通知公告
   - 公告标题。
   - 公告内容。
   - 是否启用。
   - 展示级别。
   - 邮件和短信开关及配置保存项；第一版不实际发送消息。

## 5. 后端设计

### 5.1 配置表

新增 `sys_config` 表。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `config_key` | 配置键，例如 `site.name` |
| `config_value` | 配置值，复杂值以 JSON 字符串保存 |
| `config_group` | 配置分组：`basic` / `security` / `upload` / `notice` |
| `value_type` | 值类型：`string` / `number` / `boolean` / `json` |
| `description` | 配置说明 |
| `builtin` | 是否内置配置；内置配置不允许删除 |
| `create_by` / `create_time` | 创建信息 |
| `update_by` / `update_time` | 更新信息 |
| `deleted` | 逻辑删除标识 |

第一版不开放配置项删除能力，避免误删核心配置。

### 5.2 配置 DTO

后端定义四个强类型 DTO，并在 DTO 上添加 `@Schema` 和校验注解：

- `BasicSettingsDTO`
- `SecuritySettingsDTO`
- `UploadSettingsDTO`
- `NoticeSettingsDTO`

前端按 Tab 提交对应 DTO。后端将 DTO 映射为 `sys_config` 中的一组配置项。这样比直接暴露任意 key-value 更安全，也更容易做字段级校验和默认值处理。

### 5.3 配置接口

新增 `SysConfigController`：

- `GET /system/config/group/{group}`
  - 读取某一组设置。
  - 需要 `system:settings:view`。
- `PUT /system/config/group/{group}`
  - 保存某一组设置。
  - 需要 `system:settings:edit`。

新增 `SysConfigService`：

- 按组读取配置。
- 按组保存配置。
- 读取单项配置。
- 返回默认配置。
- 保存后刷新缓存。

### 5.4 个人中心接口

扩展 `UserInfoController`：

- `GET /system/user/me`
  - 补充返回：`realName`、`gender`、`lastLoginTime`、`lastLoginIp`。
- `PUT /system/user/me/profile`
  - 当前用户修改昵称、真实姓名、邮箱、手机号、性别。
- `POST /system/user/me/avatar`
  - 当前用户上传头像。
  - 校验头像大小和类型。
  - 复用文件服务保存文件记录。
  - 更新 `sys_user.avatar`。
- `PUT /system/user/me/password`
  - 校验旧密码。
  - 校验新密码策略。
  - 更新密码。

### 5.5 配置生效策略

- 基础设置：前端读取后用于页面展示。读取失败时使用内置默认值。
- 上传策略：头像上传实时读取并校验。文件管理上传也建议接入同一策略，避免策略只对头像生效。
- 密码策略：个人修改密码和后台重置密码实时读取并校验。
- 验证码和登录失败锁定：优先接入现有认证流程的开关与参数。
- Token 时长：第一版保存配置；是否完全动态化取决于现有 `NovaProperties` 和 JWT 签发结构，实施时以不破坏登录兼容性为先。
- 通知公告：第一版保存配置，不主动推送。

### 5.6 初始化数据

新增初始化数据：

- 菜单：系统管理 / 系统设置，路径 `/system/settings`。
- 权限：`system:settings:view`、`system:settings:edit`。
- 默认配置：基础设置、安全策略、上传策略、通知公告四组默认值。

### 5.7 操作日志

纳入操作日志的行为：

- 保存系统设置。
- 修改个人资料。
- 修改头像。
- 修改密码。

密码明文、旧密码、新密码不能写入日志。

## 6. 前端设计

### 6.1 路由与页面文件

新增页面：

- `nova-admin-frontend/src/pages/profile/index.tsx`
- `nova-admin-frontend/src/pages/system/settings/index.tsx`

路由调整：

- `/profile` 加入静态登录后路由。
- `/system/settings` 加入路由组件映射和固定路由表。
- Header 用户菜单点击“个人中心”时执行 `navigate('/profile')`。

### 6.2 API 层

新增 `src/api/profile.ts`：

- `getCurrentUserProfile`
- `updateCurrentUserProfile`
- `uploadCurrentUserAvatar`
- `updateCurrentUserPassword`

新增 `src/api/settings.ts`：

- `getSettingsGroup`
- `updateSettingsGroup`
- 或为四组配置提供强类型包装函数。

所有 API 返回类型使用现有 `R<T>`，禁止使用 `any`。

### 6.3 个人中心页面交互

页面使用 `PageContainer` 和 `ProCard`。

建议布局：

- 左侧：用户卡片，包含头像上传、昵称、账号、部门、角色、登录信息。
- 右侧：Tabs。
  - 基本资料：`ProForm`。
  - 修改密码：`ProForm`。
  - 安全信息：`ProDescriptions`。

头像上传：

- 使用 Ant Design `Upload` 或 `Upload.Dragger`。
- 使用自定义请求调用头像上传接口。
- 上传成功后刷新当前用户信息，并更新 `userStore.userInfo.avatar`。
- 上传失败时展示后端 `msg`。

修改密码：

- 前端先校验两次新密码一致。
- 后端校验旧密码和策略。
- 成功后提示“密码已修改，请重新登录”，清理 token 并跳转 `/login`。

### 6.4 系统设置页面交互

页面使用 `PageContainer`、`ProCard` 和 Tabs。

每个 Tab 独立：

- 独立加载当前组配置。
- 独立保存当前组配置。
- 保存时只提交当前组 DTO。
- 保存成功后刷新当前组缓存。
- 保存失败时保留用户输入。

权限不足时：

- 无查看权限时由后端和路由权限阻止访问。
- 无编辑权限时表单只读，保存按钮隐藏或禁用。

### 6.5 状态与 i18n

- 当前用户信息继续由 `userStore` 管理。
- 资料和头像更新成功后同步刷新 `userStore`，确保 Header 立即更新。
- 系统设置不全量放入 Zustand 持久化，避免配置缓存过期。
- 基础展示配置可以使用 TanStack Query 缓存。
- 用户可见文案必须同步 `zh.ts` 和 `en.ts`。
- 用户自己的主题和语言偏好仍由 `appStore` 管理；系统默认语言和主题只作为未设置用户的默认值，不强制覆盖当前用户本地选择。

## 7. 数据流

### 7.1 个人中心

1. 进入 `/profile`。
2. 页面先展示 `userStore.userInfo` 中已有信息。
3. 调用当前用户资料接口，服务端数据返回后覆盖页面展示。
4. 保存资料后重新拉取当前用户信息。
5. 上传头像后更新后端头像字段，再刷新当前用户信息。
6. 修改密码成功后清理 token 并跳转登录页。

### 7.2 系统设置

1. 进入 `/system/settings`。
2. 按配置组加载四组配置；实现时可选择并行加载或 Tab 懒加载。
3. 用户保存某个 Tab。
4. 前端只提交该 Tab DTO。
5. 后端校验并 upsert 到 `sys_config`。
6. 服务端刷新配置缓存。
7. 前端刷新当前组缓存并提示成功。

## 8. 错误处理

- 资料更新失败：显示后端 `msg`，保留表单输入。
- 头像上传失败：类型或大小不符合策略时提示具体限制；文件服务异常时提示上传失败，原头像不变。
- 密码修改失败：旧密码错误时明确提示；新密码不符合策略时提示当前密码规则。
- 设置保存失败：当前 Tab 保持编辑状态，不影响其他 Tab。
- 权限不足：后端返回 403，前端隐藏或禁用编辑入口。
- 配置缺失：后端返回默认值并记录日志。
- 配置值损坏：后端忽略损坏值、使用默认值并记录日志，避免影响登录、上传等核心流程。

## 9. 测试策略

### 9.1 后端测试

覆盖场景：

- 当前用户资料更新只能修改本人允许字段。
- 修改密码必须校验旧密码。
- 新密码必须符合安全策略。
- 头像上传校验大小和类型。
- 配置按组读取和保存。
- 非法 group 或非法值保存失败。
- 配置缺失时返回默认值。
- 无 `system:settings:edit` 权限不能保存设置。

### 9.2 前端测试

覆盖场景：

- Header 个人中心菜单跳转 `/profile`。
- 资料保存成功后刷新当前用户信息。
- 头像上传成功后页面和 Header 头像同步更新。
- 修改密码成功后跳转登录页。
- 系统设置 Tab 独立保存；保存一个 Tab 不影响其他 Tab。
- 无编辑权限时保存按钮隐藏或禁用。
- 中英文 i18n key 完整。

## 11. 实施注意事项

- 前端包管理必须使用 pnpm。
- 不新增与现有技术栈重叠的第三方依赖。
- 后端新增 Controller 方法必须有 `@Operation`，路径参数需要 `@Parameter`。
- 用户可见文案必须走 i18n。
- 代码变更完成后不自动提交，等待用户确认。
- 系统设置涉及认证、上传和安全策略，实施时应优先保证默认值可用，避免配置缺失导致核心流程不可用。
