# Nova Admin 数据权限配置增强设计

## 1. 背景与目标

项目当前已经具备角色数据范围字段、`DataScope` 查询拦截器以及 `sys_role_dept` 关联表，但角色页面只能选择固定范围，角色部门关联没有被保存、返回或用于查询过滤。

本功能补齐角色级数据权限配置，使管理员可以为角色选择自定义部门，并让该配置真正参与受 `@DataScope` 保护的查询，同时保持现有 1～5 范围的行为不变。

本次不引入新的数据表，不增加独立菜单，不改变现有用户、角色和部门页面的路由结构。

## 2. 范围

### 包含

- 新增数据范围“自定义部门”（值 `6`）。
- 角色新增、编辑、详情接口支持 `deptIds`。
- 使用已有 `sys_role_dept` 保存角色与部门的多对多关系。
- 角色编辑弹窗展示启用部门树，并在自定义部门范围下允许勾选部门。
- 登录用户加载其角色的自定义部门集合。
- 数据权限 SQL 将固定范围条件与自定义部门条件按并集处理。
- 增加后端服务、数据权限和接口测试；执行前端类型检查。

### 不包含

- 多租户、工作流、数据权限独立菜单。
- 资源级字段权限、行级表达式编辑器。
- 数据权限审计报表和历史版本。
- 修改现有 1～5 范围的含义。

## 3. 现有范围与新增范围

| 值 | 名称 | 行为 |
| --- | --- | --- |
| 1 | 全部数据 | 不追加数据权限条件 |
| 2 | 本部门及下级 | 当前用户部门及其所有下级部门 |
| 3 | 本部门 | 当前用户所属部门 |
| 4 | 本人及下级 | 当前用户本人或当前用户部门及其下级部门 |
| 5 | 仅本人 | 当前用户创建的数据 |
| 6 | 自定义部门 | 角色配置的部门集合，精确匹配所选部门 |

选择“自定义部门”时至少需要一个有效部门。自定义部门范围不会自动展开下级部门，管理员需要明确勾选需要授权的部门。

## 4. 多角色数据权限规则

用户最终权限按所有角色取并集：

1. 任一角色为“全部数据”时，用户获得全部数据权限，忽略自定义部门集合。
2. 固定范围角色在 2～5 中取最宽范围，沿用当前数值越小权限越宽的规则。
3. 所有自定义部门角色的部门 ID 合并去重。
4. 固定范围条件与自定义部门条件使用 `OR` 连接。例如用户同时拥有“仅本人”和“自定义部门”角色时，可查询本人数据或所选部门数据。
5. 用户没有角色时保持现有默认行为：仅本人。

登录缓存中的 `LoginUser` 保留 `dataScope` 字段，并新增自定义部门 ID 集合；认证缓存刷新时重新计算两者。

## 5. 后端设计

### 5.1 DTO 与持久化

- `RoleCreateRequest`、`RoleUpdateRequest` 新增 `List<Long> deptIds`，仅当 `dataScope=6` 时生效。
- `RoleDetailDTO` 新增 `List<Long> deptIds`，用于编辑回显。
- 角色创建和更新事务中先保存角色，再清理旧的 `sys_role_dept` 关联并写入新集合。
- 非自定义范围清理关联表记录，避免切换范围后残留权限。
- 后端校验部门 ID 存在、未删除且处于启用状态；自定义范围没有部门时返回参数错误。
- 角色删除继续清理 `sys_role_dept` 关联。

### 5.2 认证与数据权限

- 角色 Mapper 增加查询用户自定义部门 ID 的方法。
- `UserDetailsServiceImpl` 在构建 `LoginUser` 时合并角色数据范围和自定义部门集合。
- `DataScopeHelper` 保留现有 1～5 分支，增加 6 分支；当存在自定义部门集合时追加 `dept_id IN (...)` 条件。
- 自定义部门条件只使用数据库中的 Long ID，不拼接用户输入文本。
- 空的自定义部门集合不会放开权限；异常或无效配置按 `1=0` 处理并记录告警日志。

### 5.3 接口

不新增接口，复用现有接口：

- `GET /api/system/dept/tree`：获取部门树。
- `GET /api/system/role/{id}`：返回 `deptIds`。
- `POST /api/system/role`：接收 `deptIds`。
- `PUT /api/system/role`：接收 `deptIds`。

所有修改后的 Controller 和 DTO 保持现有 Springdoc 注解与 `R<T>` 响应规范。

## 6. 前端设计

- 角色 API 类型新增 `deptIds: string[]` 可选字段。
- 角色弹窗复用部门树接口，不新增页面。
- 数据范围选择新增“自定义部门”选项。
- 只有选择自定义部门时显示部门树；切换到其他范围时清空待提交的 `deptIds`。
- 编辑角色时根据详情接口回显已选部门。
- 自定义部门未勾选任何节点时阻止提交，并显示国际化校验提示。
- 部门树只允许选择启用部门；节点名称、状态和层级保持现有部门页面数据。
- 所有新增文案同步维护 `zh.ts` 与 `en.ts`，通过 `t()` 使用。

## 7. 错误处理

- 角色数据范围为 6 且部门为空：返回参数校验错误。
- 部门不存在、已删除或已停用：拒绝保存并返回业务错误。
- 角色更新时部门关联保存失败：事务回滚角色字段和关联数据。
- 数据权限 SQL 生成失败：记录告警并让本次查询失败，禁止在权限条件无法生成时返回未过滤数据。

## 8. 测试与验收

### 后端

- 角色创建/更新能够保存、替换、清理 `sys_role_dept` 关联。
- 角色详情能够返回部门 ID 列表。
- 自定义范围为空、部门不存在、部门停用时校验失败。
- 单角色自定义范围生成正确 SQL。
- 固定范围与自定义范围、多角色自定义范围合并为并集。
- 全部数据范围不会附加过滤条件。
- 认证缓存能够加载自定义部门集合。

### 前端

- 角色弹窗在范围为 6 时显示部门树，其他范围隐藏。
- 编辑角色能够回显已选部门。
- 切换范围后不会提交过期部门 ID。
- 未选择部门时无法提交。
- `zh.ts` 与 `en.ts` key 同步，前端执行类型检查通过。

### 验收标准

1. 管理员可以在角色编辑弹窗选择“自定义部门”并勾选部门。
2. 保存后重新打开角色，部门选择保持一致。
3. 被授予该角色的用户查询用户列表时，只能看到本人或其角色允许的部门数据。
4. 现有 1～5 范围的角色行为不发生回归。
5. 代码、测试和类型检查通过后暂停，交由用户审查。
