# 首页仪表盘设计

## 目标

将当前的 Phase 0 占位首页替换为面向系统管理员和运维人员的只读仪表盘。首页优先展示系统业务规模，辅以可切换时间范围的活动趋势、运行态势和近期动态，帮助已登录用户快速了解系统状态。

仪表盘不提供新增、编辑、删除或跳转快捷入口。现有管理页面的权限控制保持不变。

## 已确认范围

- 首页数据必须来自真实后端接口。
- 所有已登录用户均可查看仪表盘完整数据，不对仪表盘统计、日志或监控信息施加资源级权限控制。
- 图表支持最近 7 天与最近 30 天切换。
- 首页展示最近 5 条合并后的登录和操作动态。
- 可新增 `@ant-design/charts` 用于图表，并可新增 Vitest、React Testing Library 及其必要开发依赖用于前端测试。

## 非目标

- 不修改用户、角色、日志、监控等既有页面和接口的权限模型。
- 不在仪表盘提供管理动作、快捷创建或批量操作。
- 不引入报表导出、用户自定义卡片、图表拖拽布局或数据订阅。

## 后端设计

### 模块和接口

新增 `com.nova.admin.modules.dashboard` 模块，包含：

- `DashboardController`：暴露 `GET /dashboard/overview`，声明 `@Tag` 与 `@Operation`。
- `DashboardService` 和实现：聚合统计、趋势、运行摘要与近期动态。
- `DashboardOverviewDTO`：接口响应 DTO；按用途拆分内部 DTO，避免使用 `Map` 作为公开响应。
- 所需 Mapper 查询：统计总数、按日聚合的登录/操作次数，以及最近记录读取。

接口参数为 `range`，仅允许 `7d` 或 `30d`，默认 `7d`。接口保持全局认证要求，但不添加模块资源级 `@PreAuthorize`；因此所有已登录用户都能取得完整概览。接口仍使用项目统一的 `R<DashboardOverviewDTO>` 响应格式。

### 响应模型

`DashboardOverviewDTO` 的 `stats`、`trend`、`distribution`、`runtime` 和 `activities` 均为独立区块；每个区块包含 `available` 布尔值和其领域数据。稳定字段如下：

- `stats`：用户、角色、部门、菜单、文件、定时任务的总数。
- `trend`：连续日期序列，每日包含登录次数与操作次数；缺失日期补零，保证图表横轴连续。
- `distribution`：与 `stats` 对应的业务资产分类及数值，用于横向柱状图。
- `runtime`：应用名称、版本、在线状态、在线用户数、CPU、内存和 JVM 使用率。
- `activities`：登录日志和操作日志按发生时间降序合并后的前 5 条记录，包含类型、执行人、摘要、时间和状态。
- `updatedAt`：服务端生成的概览时间。

统计、趋势、活动和资源摘要的查询在 Service 层完成组装。活动记录先分别读取有限条目，再合并、排序和截取，以避免在前端处理审计数据。趋势的起始日至当天均使用同一业务时区生成，避免 7 天和 30 天切换时出现日期空洞。

### 降级策略

业务统计、趋势和活动查询失败时，接口将对应区块的 `available` 设为 `false` 并返回空数据，不因单一区块失败导致整个接口失败。监控信息读取失败时，`runtime.available` 为 `false`，同时保留应用名称、版本和离线/不可用状态，资源数值为空。后端记录异常详情，不向用户暴露内部错误。

## 前端设计

### 数据流

新增 `src/api/dashboard.ts`，定义请求函数和精确的领域类型。首页使用一个 TanStack Query：

```ts
['dashboard', 'overview', range]
```

查询首次加载完整概览，并以 30 秒间隔刷新。切换 `7d` 与 `30d` 时使用新的 query key 请求对应趋势数据，同时保持页面尺寸稳定。接口错误提供本地化错误反馈和重试入口；区块可用但为空时显示局部空态。

### 页面组成

`src/pages/dashboard/index.tsx` 只负责范围状态、查询状态和区域编排。局部组件位于 `src/pages/dashboard/components/`，一文件一个组件：

- `DashboardHeader`：当前日期、应用在线状态和数据更新时间。
- `DashboardStatCards`：六项业务规模数据卡片。
- `ActivityTrendChart`：7 天/30 天分段切换和登录/操作双折线图。
- `AssetDistributionChart`：业务资产横向柱状图。
- `RuntimeOverview`：在线用户、应用状态与 CPU、内存、JVM 使用率进度环。
- `RecentActivities`：最近五条动态。

页面按照以下视觉顺序排列：

1. 顶部概览，提供轻量状态信息但不放操作按钮。
2. 首屏业务规模数据卡片，突出系统资产总量。
3. 左侧活动趋势折线图、右侧资产规模横向柱状图。
4. 系统态势与近期动态。

桌面端使用响应式栅格；窄屏下图表、运行态势和动态区按顺序单列排列。使用现有 Ant Design、ProComponents 和 Tailwind 视觉语言：白色工作面、清晰间距、低饱和色彩和紧凑信息密度。不增加营销式横幅、装饰性背景或嵌套卡片。

### 图表

新增 `@ant-design/charts`：

- `Line` 呈现登录次数和操作次数的日趋势，带本地化 Tooltip 与图例。
- `Bar` 呈现用户、角色、部门、菜单、文件和任务的规模比较。
- 使用 Ant Design 的 `Progress` 仪表式进度环呈现 CPU、内存与 JVM 使用率，不引入额外图表类型。

图表没有数据时保留固定高度，并展示本地化空态。所有用户可见标题、说明、状态、Tooltip、时间范围和空态均补充到 `zh.ts` 与 `en.ts`。

## 错误处理与可访问性

- 首次加载使用与最终区块尺寸相符的骨架，避免布局跳动。
- 时间范围切换仅为趋势区域展示加载态，统计卡和其他内容不闪烁。
- 请求整体失败时展示明确的错误反馈及重试按钮。
- 图表颜色不单独表达结果；Tooltip、图例、标签和文本状态提供冗余信息。
- 所有百分比限制在 0 到 100；缺失监控值显示不可用而非伪造为 0。

## 测试与验证

后端新增 JUnit 5 单元测试，覆盖：

- `7d` 和 `30d` 日期范围及缺失日期补零。
- 统计、分类数据和活动记录的组装、排序与截取。
- 无日志或无业务数据时的空结果。
- 监控信息异常时的局部降级。

前端配置 Vitest、React Testing Library、`@testing-library/user-event` 与 `@testing-library/jest-dom`。新增组件或工具测试，覆盖：

- 7 天/30 天切换触发正确 query key。
- 加载、请求失败、区块空数据和可用数据状态。
- 趋势与资产图表接收的转换后数据。
- 最新动态的类型、状态和时间渲染。

实现完成后运行前端的 `pnpm lint`、`pnpm type-check`、相关 Vitest 测试与生产构建；运行后端相关 JUnit 5 测试。由于公开 API 与新增模块会变更，实施阶段同步更新 `README.md` 和 `CHANGELOG.md`。

## 变更边界

预计修改或新增的范围：

- 后端 Dashboard 模块及其 Mapper、测试。
- 前端 dashboard API、页面、局部组件、图表测试和测试配置。
- `zh.ts` 与 `en.ts` 的同步翻译。
- 前端 `package.json` 和锁文件中的已获批准依赖。
- `README.md` 和 `CHANGELOG.md` 的公共接口与功能记录。

不触碰既有业务管理页的行为、路由、数据模型或权限判定。
