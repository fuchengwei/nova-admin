# 接口权限独立菜单设计

## 目标

将接口权限从菜单管理页内嵌 Drawer 提升为系统管理下的独立菜单页面，保留现有独立接口权限表、接口发现注册、角色分配和在线权限刷新能力。

## 页面与路由

- 新增菜单：名称使用 i18n，类型为 `C`，路径 `/system/api-permission`，组件标识 `system/api-permission/index`，图标使用 `ApiOutlined` 对应图标。
- 前端新增 `ApiPermissionPage`，复用现有接口权限表格和角色配置弹窗。
- 静态路由和动态组件映射同步增加该页面；不增加前端 fallback 菜单。
- 菜单管理页移除“接口权限”按钮、Drawer 引用及相关状态。

## 权限与兼容

- 页面访问继续使用现有 `system:menu:list` 权限。
- 接口注册和角色分配继续使用现有 `system:menu:edit` 权限及超级管理员豁免规则，避免引入权限自举问题。
- 初始化 SQL 增加独立菜单种子数据。
- 菜单和角色关联只在 `sql/init.sql` 中初始化，不增加运行时迁移器。
- 不删除、不修改现有菜单按钮权限和接口权限关联数据。

## 组件边界

- `ApiPermissionPage` 负责页面标题、权限表格和页面级布局。
- 接口权限表格和角色配置逻辑保留在页面局部组件目录，继续通过 `ProTable.request` 获取数据、通过 mutation 执行写操作。
- 表格按接口 URL 展示，HTTP 方法使用 Tag，角色使用多选下拉框。

## 测试与验证

- 后端：验证初始化 SQL 包含菜单和接口权限结构，现有接口权限服务与控制器测试继续通过。
- 前端：验证类型检查、生产构建，并确认菜单管理页不再渲染 Drawer 按钮。
- 执行 `git diff --check`，不自动提交。
