# Nova Admin — 表格空值统一显示设计文档

> 版本：v1.0
> 日期：2026-07-25
> 类型：前端展示规范 / 表格空值渲染
> 关联分支：`master`

---

## 一、背景与目标

当前前端各页面表格对空值的显示方式并不统一：部分列使用 `value || '-'`，部分列使用 `value ?? '-'`，还有一些列没有专门处理空值。这会带来两个问题：

1. **用户体验不一致**：同样是空字段，不同页面可能显示为空白、`-`，或保留不同的回退逻辑；
2. **实现容易出错**：`value || '-'` 会把 `0`、`false` 这类合法值误判为空，而 `value ?? '-'` 又不会覆盖空字符串 `''`。

本次改造目标是：

- 在项目范围内统一表格文本字段的空值显示规则；
- 明确只有 `null / undefined / ''` 视为空，统一显示 `-`；
- 明确 `0`、`false`、非空字符串都保留原值；
- 通过公共工具函数收敛规则，避免每个页面重复手写判空逻辑。

---

## 二、关键决策摘要

| 决策点 | 选型 |
| --- | --- |
| 统一方式 | 新增公共工具函数 |
| 判空范围 | `null`、`undefined`、`''` |
| 非空保留 | `0`、`false`、普通字符串、数字原样保留 |
| 适用对象 | 表格中的纯文本展示字段 |
| 特殊列处理 | 链接、Tag、单位拼接、自定义 JSX 保留页面级 `render`，但内部遵守同一规则 |

---

## 三、规则定义

### 3.1 空值判定

以下值统一显示为 `-`：

- `null`
- `undefined`
- `''`

以下值不视为空：

- `0`
- `false`
- `'0'`
- `'false'`
- 其它非空字符串

### 3.2 使用边界

该规则适用于：

- `ProTable` 文本列
- 需要直接回显后端字段的普通单元格
- 不带复杂视觉逻辑的只读表格内容

该规则**不直接接管**以下场景：

- `Tag` / 状态徽标
- 链接列
- 图片 / 预览列
- 带单位拼接的数值列（如 `GB`、`ms`）
- 自定义 JSX 结构列

这些特殊列继续保留各自 `render`，但内部若需要显示纯文本回退，也应复用同一个工具函数或等价逻辑。

---

## 四、实现方案

### 4.1 公共工具函数

在 `src/utils/` 下新增一个公共工具函数，职责单一：

- 输入任意待展示值；
- 若值属于 `null / undefined / ''`，返回 `-`；
- 否则返回原值。

该函数不负责 JSX 包装、不负责格式化单位、不负责颜色或样式。

### 4.2 页面接入方式

将现有表格中零散的：

- `value || '-'`
- `value ?? '-'`
- `render: (v) => v || '-'`

逐步替换为统一工具调用。

对于特殊列：

- 如果列渲染的是链接，先判断是否为空；为空则显示 `-`，不为空再渲染链接；
- 如果列渲染的是 `Tag`，先判断值是否为空；为空则显示 `-`，否则继续按原有样式渲染；
- 如果列渲染的是单位拼接，先判断底层值是否为空，避免出现 `undefined GB`、`nullms` 等异常文本。

## 五、首批覆盖范围

首批优先覆盖当前已出现较多手写空值逻辑的表格页面：

- `src/pages/system/dict/index.tsx`
- `src/pages/system/dict/components/DictDataModal.tsx`
- `src/pages/system/log/index.tsx`
- `src/pages/system/role/index.tsx`
- `src/pages/system/user/components/columns.tsx`
- `src/pages/infra/file/index.tsx`
- `src/pages/monitor/server/index.tsx`
- 以及其它存在同类写法的 `ProTable` 页面

目标不是只修当前字典页，而是把“表格文本空值显示为 `-`”沉淀为全项目一致规范。

---

## 六、非目标

本次改造不包含以下内容：

- 不修改表单输入框 placeholder 策略；
- 不统一 `ProDescriptions`、详情页、卡片组件的空值策略；
- 不改变后端返回数据；
- 不对 `0` / `false` 做显示替换；
- 不引入新的全局表格封装组件。

这样可以把改动范围稳定控制在“前端表格展示规则统一”。

---

## 七、验证方式

### 7.1 静态检查

在 `nova-admin-frontend` 目录执行：

```bash
pnpm format
```

```bash
pnpm lint
```

```bash
pnpm type-check
```

### 7.2 页面验证

重点检查以下情况：

1. 原本为空白的表格文本字段现在显示 `-`；
2. 空字符串 `''` 能正确显示 `-`；
3. `0` 不会被误显示成 `-`；
4. `false` 不会被误显示成 `-`；
5. 链接、Tag、单位拼接列在空值时显示 `-`，非空时保持原样；
6. 各页面显示风格一致，不再混用多套判空逻辑。

---

## 八、与现有代码风格一致性

本方案遵循项目当前规范：

- 将共用逻辑抽到 `src/utils/`，而不是在各页面重复复制；
- 保持页面列定义职责清晰，不引入额外抽象层级；
- 以渐进替换方式落地，避免一次性引入过重的全局封装。

最终结果应是：项目中所有表格文本列的空值展示规则统一、可复用、可维护。
