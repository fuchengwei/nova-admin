# 首页仪表盘运营控制台重设计

## 目标

将首页改为高密度运营控制台，而非以趋势图为中心的概览页。视觉参考采用浅青灰画布、独立白色数据卡与大面积白色工作面；所有内容继续来自现有概览接口，不虚构余额、消费或 Token 等业务数据。

## 信息架构

1. 顶部保留页面标题、服务状态和更新时间，缩短垂直空间。
2. 首屏只保留四张紧凑规模卡：用户、角色、部门、文件。定时任务不再单独占用卡片。
3. 运行态势收缩为一条状态信息带，展示服务状态、在线用户、CPU、内存和定时任务数量。CPU 和内存直接显示百分比，不再使用圆环或进度条。
4. 活动趋势与近期动态并列成为主工作区，趋势为宽栏，动态为窄栏。动态继续以时间线组织最近登录和操作记录。
5. 趋势工具栏包含 7 天/30 天切换。30 天横轴只显示间隔日期，避免标签重叠；Y 轴保留自适应比例以准确表达峰值。

## 视觉系统

- 画布：继承后台布局的 `#F0F2F5`
- 工作面：`#FFFFFF`
- 边框：`#E6ECEF`
- 主文字：`#172033`
- 辅助文字：`#7B8798`
- 活动蓝：`#3B82F6`
- 健康绿：`#10B981`
- 强调紫：`#8B5CF6`
- 注意橙：`#F59E0B`

页面不再设独立背景或最大内容宽度，直接铺满后台内容区，只保留正常的 24px 内容内边距。卡片使用 8px 圆角、轻量边框和非常克制的阴影。规模卡统一使用蓝色图标识别，绿色仅用于服务健康状态，避免彩虹色造成的视觉噪声。响应式布局在窄屏下依次降为两列和单列。

## 变更范围

- 重构 `DashboardStatCards` 为四张紧凑规模卡和一条运行状态信息带。
- 删除 `RuntimeOverview` 的圆环展示，保留其业务数据并融入状态信息带。
- 调整仪表盘页面结构：指标卡、状态信息带、趋势与动态双栏主工作区。
- 调整 `ActivityTrendChart` 的工具栏、坐标轴和高度，保持范围切换与局部加载行为。
- 调整 `RecentActivities` 的容器密度和时间线表现。
- 复用现有 API 类型和 i18n；仅在缺少的辅助文案时同步增补中英文翻译。

## 验证

- 在 7 天和 30 天范围下检查趋势横轴可读性。
- 检查桌面四列、平板两列和手机单列布局。
- 运行 `pnpm type-check`、`pnpm build` 和仪表盘后端定向测试。
