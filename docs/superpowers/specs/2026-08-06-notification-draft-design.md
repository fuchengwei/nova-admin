# 消息草稿闭环设计

## 目标

让管理员能够创建、查看、继续编辑、保存、发布或删除站内消息草稿。草稿在服务端持久化；从草稿立即发布或定时发布时复用同一条消息记录，不产生重复消息。

## 范围

- 草稿列表通过现有发布记录列表按 `DRAFT` 状态筛选展示。
- 草稿可回填标题、内容、链接、接收范围及已选接收对象。
- 草稿可再次保存、转为立即发布或转为定时发布。
- 草稿可软删除；定时消息维持现有取消语义。
- 已发送、发送中、失败或已取消的消息不可编辑或删除。

不包含浏览器本地自动保存、草稿版本历史、协同编辑和草稿权限模型调整。沿用当前发布记录的全局管理权限：拥有消息发布权限的管理员可以管理草稿。

## 接口

保留 `POST /system/notification/publish` 创建新消息。新增和调整的接口如下：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/system/notification/{id}/draft` | 返回状态为 `DRAFT` 的可编辑草稿；其他状态返回业务错误。 |
| `PUT` | `/system/notification/{id}` | 更新草稿。`mode=DRAFT` 保存草稿，`IMMEDIATE` 立即发布，`SCHEDULED` 转为定时发送。 |
| `DELETE` | `/system/notification/{id}` | 仅软删除 `DRAFT` 状态消息。 |
| `POST` | `/system/notification/{id}/cancel` | 保持现有行为，仅取消 `SCHEDULED` 消息。 |

所有接口沿用发布权限、统一 `R<T>` 响应和 Springdoc 的 `@Operation`、`@Parameter` 注解。草稿读取响应使用专用 DTO，`recipientIds` 以数组返回，避免向前端泄漏数据库 JSON 文本。

## 状态转换

```text
新建 + DRAFT         -> DRAFT
DRAFT + DRAFT        -> DRAFT
DRAFT + SCHEDULED    -> SCHEDULED
DRAFT + IMMEDIATE    -> SENT
DRAFT + DELETE       -> soft deleted
SCHEDULED + CANCEL   -> CANCELED
```

保存草稿仅校验接收范围的结构完整性，不要求当前存在可投递的启用用户。转为立即发布时重新解析当前启用接收人并创建收件明细；没有可投递用户时失败，草稿保持原样。转为定时发送时要求计划时间晚于当前时间；实际执行时仍重新解析接收人。

## 后端实现

- 在 `SysMessageMapper` 增加草稿查询、草稿更新和草稿软删除 SQL，均以 `status = 'DRAFT'` 作为并发状态保护。
- `NotificationService` 负责读取草稿、更新消息实体和删除草稿；`NotificationPublishService` 负责模式校验、接收人序列化和状态转换。
- 草稿更新接口使用当前操作者作为发布人，清除旧的计划时间和错误信息；转定时时写入新的计划时间；立即发布后通过现有 `deliver` 写入收件明细并投递事件。
- 查询草稿时解析 `recipient_ids` JSON。无法解析历史异常数据时返回业务错误，不允许用错误范围覆盖草稿。

## 前端实现

- API 层新增草稿读取、更新和删除函数与精确类型。
- 发布表单接受可选草稿并以草稿 ID 作为重建键，确保编辑时字段、模式和接收人预览完整回填。
- 草稿编辑时保留发布方式选择：保存草稿、立即发布和定时发布均调用草稿更新接口。
- 发布记录表增加状态筛选；草稿记录显示继续编辑与删除，定时消息显示取消。操作成功后刷新表格，并由页面切换回发布标签以继续编辑草稿。
- 新增用户可见文案在 `zh.ts` 和 `en.ts` 同步维护。

## 错误处理

- 读取、更新或删除非草稿消息返回明确业务错误。
- 删除操作只允许草稿；取消操作只允许定时消息。
- 定时模式拒绝当前时间或过去时间。
- 立即发布拒绝无启用收件人的范围，且不改变草稿内容或状态。
- 前端对接口失败显示后端错误消息，并仅在成功时刷新或切换页面状态。

## 测试

- `NotificationPublishServiceImplTest`：草稿重复保存、草稿转定时、草稿立即发布、非草稿更新、过去定时时间、即时发布无有效收件人。
- `NotificationServiceImplTest` 或 Mapper 测试：草稿读取解析、更新和软删除的状态限制。
- 前端现有测试环境尚未配置；不新增测试框架或依赖。实现保持 API 类型和表单状态可由后续 Vitest + RTL 覆盖。

## 验收标准

1. 管理员能创建草稿，并在发布记录中通过草稿状态筛选找到它。
2. 草稿继续编辑后，所有消息字段与接收范围准确回填。
3. 再次保存不会新增消息记录。
4. 草稿可转为立即发布或定时发送，状态和收件人行为符合现有发布规则。
5. 草稿可删除，定时消息可取消，其他状态不展示对应操作且后端拒绝请求。
