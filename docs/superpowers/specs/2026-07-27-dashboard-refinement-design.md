# 首页仪表盘信息收缩与视觉重排设计

## 目标

将首页从等权资源展示收缩为日常判断面板。系统管理员和运维人员打开首页时，应先判断组织规模、活动变化、服务健康和最近操作，而不是浏览没有直接决策价值的资源清单。

## 数据范围

保留五项规模指标：用户、角色、部门、文件、定时任务。

移除菜单数量和业务资产分布图。菜单数量不反映业务规模、运行风险或待处理事项；分布图与规模卡片表达重复，移除后可把页面主视觉留给趋势信息。

后端概览接口不再查询、返回或测试 `menuCount` 和 `distribution`。前端类型、翻译和组件同步删除对应字段与文案。

## 信息架构

页面按用户判断顺序组织：

1. 顶部状态摘要：页面标题、服务在线状态和数据更新时间。
2. 规模带：五项紧凑规模指标，以细分隔线组织为同一信息单元。
3. 主工作区：活动趋势作为宽主面，运行态势作为右侧窄栏。
4. 审计动态：最近五条登录和操作记录作为全宽时间线。

窄屏下规模带以两列换行，趋势、运行态势和动态按上述顺序单列展示。趋势图和运行指标保留稳定高度，避免动态内容改变布局。

## 视觉系统

- 画布：`#F5F7FA`
- 工作面：`#FFFFFF`
- 主文字：`#1F2937`
- 活动蓝：`#1677FF`
- 状态绿：`#16A34A`
- 注意琥珀：`#D97706`

页面使用白色工作面、石墨文字和克制的细分隔线。活动图仅使用蓝色系，绿色和琥珀只用于服务、成功和异常状态。正文沿用现有 sans-serif；统计数值使用系统等宽字体，增强扫描与比较。不得新增背景渐变、营销式横幅、嵌套卡片或纯装饰性元素。

## 组件调整

- `DashboardStatCards` 改为包含五项指标的规模带。
- `ActivityTrendChart` 扩大为主面板，保留 7 天/30 天切换，并使用克制区域填充帮助比较变化。
- 删除 `AssetDistributionChart`。
- `RuntimeOverview` 维持紧凑圆环与在线人数，状态颜色必须配合明确文本。
- `RecentActivities` 改为单列时间线，显示类型、执行人、摘要、状态和时间。

加载、局部不可用、整体失败和范围切换延续既有行为：初始显示骨架，局部区块独立降级，整体失败提供重试，范围切换只刷新趋势区域。

## 验证

- 补充 Dashboard Service 测试，确保不再组装菜单与分布数据。
- 运行前端 `pnpm type-check`、`pnpm lint` 和 `pnpm build`，以及后端相关 JUnit 5 测试。
- 前端 RTL 测试在 registry 可用并安装 Vitest 依赖后补充。
- 人工检查中英文、7 天/30 天切换、窄屏布局和无数据状态。
