# 系统设置页 UI 打磨设计文档

> 日期：2026-07-26  
> 状态：已获对话内设计确认，待用户审阅书面规格  
> 范围：系统设置页视觉与交互打磨，少量同步优化个人中心展示层  
> 项目：Nova Admin

## 1. 背景与目标

当前系统设置页虽然已经具备基础功能，但页面观感更接近“分组表单集合”，缺少一个成熟企业后台“配置中心”的稳定气质。用户明确反馈“系统设置不好看”，并希望继续做一轮更精致的 UI 打磨。

本轮设计目标不是扩展业务能力，而是在不改变核心接口和配置模型的前提下，重塑系统设置页的视觉层级、概览方式、编辑入口与长内容体验，让页面更像企业控制台里的系统配置中心。

同时，个人中心页允许做少量展示层同步优化，用于与系统设置页整体风格保持一致，但不扩展功能边界。

## 2. 范围

### 2.1 包含

- 系统设置页整体布局重构。
- 系统设置页配色、卡片层级、模块摘要样式优化。
- 只读概览 + 弹窗编辑交互固化。
- Logo 改为上传优先，不再以 URL 录入为主交互。
- 通知公告弹窗的滚动与保存按钮可达性优化。
- 系统设置页模块总览信息重排。
- 个人中心页少量视觉细节优化：只读感强化、信息去重、时间格式优化。

### 2.2 不包含

- 新增设置模块。
- 修改后端接口契约。
- 新增富文本编辑器、颜色选择器、拖拽排序等增强能力。
- 调整权限模型。
- 调整数据库结构。
- 修改主题系统或全局设计 token 体系。

## 3. 视觉方向

本轮采用“企业控制台感”方向，并以“模块概览优先”为首页第一视觉层。

设计关键词：

- 稳定
- 清晰
- 克制
- 可管理
- 有模块识别度但不花哨

目标效果不是营销页，也不是普通 CRUD 表单页，而是一个平台管理员一进入就能迅速理解“当前系统配置版图”的配置中心。

## 4. 页面结构设计

### 4.1 系统设置页总体结构

页面分为三层：

1. 顶部说明区
   - 页面标题：系统设置
   - 简短副标题：用于解释这是统一管理平台展示、安全、上传与通知策略的配置中心
2. 第一屏模块总览区
   - 四张核心模块卡片矩阵：基础设置 / 安全策略 / 上传策略 / 通知公告
   - 每张卡片展示模块识别信息与关键摘要
3. 模块详细只读区
   - 在总览卡之下，按模块顺序展示更完整的只读详情
   - 用户不需要进入编辑状态也能读懂当前配置

页面主体允许自然滚动，避免在主页面上叠加过多内部滚动容器。

### 4.2 个人中心页总体结构

个人中心页继续保持“只读展示 + 弹窗编辑”模式，但进一步增强信息层级：

- 左侧为资料主卡片
- 右侧为资料详情卡 + 安全信息卡
- 不再展示“权限数量”这类低价值信息
- 保留头像上传入口，但去掉“前往系统设置”按钮
- 最近登录时间使用用户可读格式展示

## 5. 模块卡片与只读摘要设计

### 5.1 基础设置卡

卡片摘要展示：

- 系统名称
- 默认语言
- 主题色
- Logo 预览缩略图

只读详情展示：

- 系统名称
- 浏览器标题
- 默认语言
- 主题色
- 版权文本
- Logo 预览

卡片应强调“品牌与展示配置”属性，因此允许比其他模块更强一点的视觉识别度。

### 5.2 安全策略卡

卡片摘要展示：

- 密码最小长度
- 验证码状态
- 登录失败锁定次数
- 锁定分钟数

只读详情展示分为两个语义组：

- 密码策略
- 登录保护

在只读详情中补充：是否要求数字 / 字母 / 特殊字符、Token 时长等信息。

### 5.3 上传策略卡

卡片摘要展示：

- 通用最大上传大小
- 头像最大上传大小
- 通用允许类型
- 头像允许类型

只读详情分为：

- 通用上传
- 头像上传

摘要中允许对类型字符串做简短截断，但详情区应能完整阅读。

### 5.4 通知公告卡

卡片摘要展示：

- 公告标题
- 启用状态
- 公告级别
- 邮件 / 短信通知状态

只读详情分为三段：

- 公告内容
- 邮件通知
- 短信通知

公告内容默认展示更多文本，但应限制极端情况下的视觉拉伸，必要时在只读区局部滚动。

## 6. 编辑交互设计

### 6.1 统一原则

系统设置页所有模块遵循统一交互：

- 页面默认只读
- 每个模块只有一个主编辑入口
- 点击“编辑”后弹出对应模块的 `ModalForm`
- 保存成功后关闭弹窗并刷新当前模块摘要与详情
- 页面主体不直接展示编辑表单

这样做的目标是把系统设置从“表单页”提升为“配置中心”。

### 6.2 基础设置弹窗

布局：

- 左侧：Logo 预览 + 上传按钮
- 右侧：系统名称、浏览器标题、默认语言、主题色、版权文本

关键要求：

- 不再把 Logo URL 作为主要交互
- Logo 通过上传得到最终地址
- `logoUrl` 仍可作为内部存储值存在，但不再作为用户心智中的输入字段

### 6.3 安全策略弹窗

表单分两组：

- 密码策略
- 登录保护

字段不应机械地 9 个平铺，而应按语义分块，以降低阅读负担。

### 6.4 上传策略弹窗

弹窗保持简洁，重点是：

- 上传大小限制
- 类型字符串输入说明
- 通用上传与头像上传边界清晰

### 6.5 通知公告弹窗

这是本轮重点优化对象。

要求：

- 弹窗更宽
- body 设置最大高度
- body 内部滚动
- footer 始终可达
- 公告内容区域更加显眼
- 邮件 / 短信配置作为两个次级分组存在

它的体验应更像“可编辑面板”，而不是简单的长表单。

## 7. 视觉系统建议

### 7.1 页面背景与卡片

- 页面背景：浅灰蓝系后台底色
- 卡片：白底、柔和阴影、较大圆角
- 模块卡片统一高度或视觉重心一致

### 7.2 模块识别色

为四个模块提供克制但明确的识别色：

- 基础设置：蓝
- 安全策略：深靛蓝
- 上传策略：青绿
- 通知公告：琥珀

这些颜色主要用于图标底板、轻量标签和局部强调，不做大面积铺满。

### 7.3 图标与状态标签

图标不仅是装饰，而是模块语义入口的一部分：

- 图标放在模块总览卡左上或左侧
- 使用浅色圆角底板承载
- 图标与模块识别色一致

状态标签规则：

- 启用：绿色
- 禁用：中性灰
- 风险或限制类：橙色
- 安全关键项：蓝紫色

每张卡只展示 1~2 个最重要状态标签，避免页面过于嘈杂。

## 8. 滚动与布局行为

### 8.1 页面层

- 页面主体支持自然滚动
- 尽量减少多层嵌套滚动
- 第一屏总览卡之后的详细模块区可以随着页面整体向下滚动

### 8.2 只读内容区

- 普通详情区尽量完整展开
- 公告内容这种长文本允许局部限高后滚动

### 8.3 弹窗层

所有设置弹窗都建议统一支持：

- 最大高度限制
- body 内部滚动
- footer 操作区保持可见

其中通知公告弹窗必须严格满足这一点，避免保存按钮被内容推到可视区域之外。

## 9. 个人中心联动优化

虽然本轮重点是系统设置页，但个人中心应同步遵守更成熟的展示层级：

- 强化左侧资料主卡的识别度
- 保持默认只读
- 资料编辑与密码编辑通过弹窗完成
- 去掉“权限数量”展示
- 去掉“前往系统设置”入口
- 最近登录时间格式化
- 减少同一信息在多个区域重复出现

## 10. 实施边界

本轮实现只改：

- 布局
- 视觉层级
- 卡片摘要表达
- 只读信息组织方式
- 弹窗交互体验
- 滚动与保存按钮可达性

不改：

- 后端接口结构
- 设置业务能力
- 数据模型
- 权限体系
- 新增复杂控件依赖

## 11. 验收标准

完成后应达到：

1. 系统设置页第一眼像“配置中心”，而不是“表单页”。
2. 四个模块边界清楚、摘要信息足够支撑快速扫描。
3. 编辑统一通过弹窗完成，页面主体默认只读。
4. Logo 通过上传设置，不再依赖 URL 输入心智。
5. 通知公告弹窗长内容可滚动，保存按钮始终可达。
6. 个人中心页与系统设置页在风格上更一致、更成熟。
