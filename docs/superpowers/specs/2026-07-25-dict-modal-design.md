# Nova Admin — 字典管理页交互改造设计文档

> 版本：v1.0
> 日期：2026-07-25
> 类型：前端页面交互重构 / 字典管理
> 关联分支：`master`

---

## 一、背景与目标

当前字典管理页 `src/pages/system/dict/index.tsx` 同时承载字典类型与字典数据两块内容，并通过 `Tabs` 在“字典类型 / 字典数据”之间切换。进入字典数据列表依赖两层交互：先点击字典类型表格操作列中的“字典数据”按钮，再切换到独立的数据页签。

这套交互存在三个问题：

1. **主流程不够直观**：字典数据天然从属于某个字典类型，但当前入口隐藏在操作列里，且需要页面内导航切换；
2. **页面层级偏重**：用页签承载从属数据，会让字典类型与字典数据看起来像两个并列模块，而不是“列表 + 详情/子数据”的关系；
3. **实现职责过多**：当前单文件同时维护两套表格、两套弹窗和一套页签状态，已明显超过项目推荐的单文件体量。

本次改造目标是：

- 将字典类型表中的“字典类型”列做成高亮可点击文本；
- 点击后直接打开字典数据弹框表格，不再保留独立的字典数据页签；
- 删除操作列中的“字典数据”按钮；
- 将“描述”列调整到“状态”列之前；
- 在不改变现有接口与 CRUD 能力的前提下，重组页面结构，使代码更符合现有前端规范。

---

## 二、关键决策摘要

| 决策点 | 选型 |
| --- | --- |
| 主页面结构 | 仅保留字典类型 `ProTable`，移除 `Tabs` |
| 字典数据入口 | 字典类型列渲染为高亮可点击文本 |
| 字典数据承载方式 | 页面级 `Modal` 弹框内嵌 `ProTable` |
| 代码组织 | 提取 `DictDataModal.tsx` 局部组件，避免 `index.tsx` 继续膨胀 |
| 现有接口 | 完全复用 `getDictDataPage/createDictData/updateDictData/deleteDictData` |
| 交互收尾 | 弹框关闭时清理当前选中字典类型与局部编辑状态 |

---

## 三、架构与文件调整

### 3.1 页面主体

保留 `src/pages/system/dict/index.tsx` 作为字典管理页入口，但只负责以下职责：

- 渲染字典类型 `ProTable`；
- 管理字典类型新增/编辑弹窗；
- 持有当前被点击的字典类型 `selectedDictType`；
- 控制字典数据弹框开关；
- 将所选字典类型传给字典数据弹框组件。

移除以下状态与结构：

- `activeTab`；
- 页面级 `Tabs` 容器；
- “返回字典类型页”的按钮；
- 独立 `data` 页签的 children 渲染逻辑。

### 3.2 局部组件拆分

新增页面局部组件：

- `src/pages/system/dict/components/DictDataModal.tsx`

该组件专门负责字典数据相关交互：

- 弹框标题与当前字典类型信息展示；
- 字典数据 `ProTable` 查询、分页、刷新；
- 新增/编辑字典数据的 `ModalForm`；
- 删除确认与刷新；
- 组件内部的 `editingData`、`dataModalOpen`、`actionRef` 等局部状态。

这样可以把“字典类型页主体”和“字典数据弹框工作区”明确拆开，符合现有规范中“页面局部组件放在 `pages/<module>/components/`”与“大文件必须拆分”的要求。

## 四、页面布局与交互设计

### 4.1 字典类型表格列调整

字典类型表格列顺序调整为：

1. 字典名称
2. 字典类型
3. 描述
4. 状态
5. 创建时间
6. 操作

其中：

- **字典类型列**：渲染为高亮文本按钮或链接样式文本，作为查看字典数据的唯一入口；
- **描述列**：固定在状态列之前，满足新的视觉顺序要求；
- **操作列**：仅保留编辑、删除两个动作，不再展示“字典数据”按钮。

### 4.2 字典类型点击行为

点击字典类型列后：

1. 设置当前选中的字典类型记录；
2. 打开字典数据弹框；
3. 弹框内表格使用该记录的 `id` 作为 `typeId` 查询条件；
4. 弹框顶部展示当前字典名称与字典类型编码，帮助用户确认上下文。

### 4.3 字典数据弹框形态

字典数据使用 `Modal` 承载，不再作为整页内容展示。弹框内主体结构为：

- 顶部：当前字典类型信息（名称 + 类型编码）；
- 中部：字典数据 `ProTable`；
- 工具栏：新增数据按钮；
- 行内操作：编辑、删除；
- 弹框内二级 `ModalForm`：新增/编辑字典数据。

该设计保持“在当前页面完成上下文任务”，避免用户在字典类型与字典数据之间反复切换页面区域。

## 五、数据流与状态管理

### 5.1 主页面状态

`index.tsx` 维护以下核心状态：

- `selectedDictType: DictTypeRecord | null`：当前准备查看数据的字典类型；
- `dictDataModalOpen: boolean`：字典数据弹框是否打开；
- `typeModalOpen / typeEditMode / editingType`：沿用现有字典类型新增编辑逻辑。

主页面不再维护字典数据编辑状态，避免跨职责状态耦合。

### 5.2 弹框内部状态

`DictDataModal.tsx` 维护：

- 表格 `actionRef`；
- 字典数据新增/编辑弹窗开关；
- `editingData` 与编辑模式标记；
- 对应的 `useMutation` 实例。

当 `selectedDictType` 变化且弹框打开时，`ProTable.request` 使用当前 `selectedDictType.id` 拉取字典数据分页。

### 5.3 关闭与重置规则

关闭字典数据主弹框时：

- 清空当前选中的字典类型；
- 清理弹框内部编辑状态；
- 下次重新打开时按新类型重新发起查询。

这样可避免上一次打开残留的编辑状态或标题信息污染下一次操作。

## 六、错误处理与成功反馈

沿用现有页面约定，不新增新的错误处理机制。

### 6.1 表格请求失败

字典数据 `ProTable.request` 调用失败时，继续返回：

```ts
{ data: [], success: false, total: 0 }
```

由表格维持失败态，不额外打断页面主流程。

### 6.2 新增/编辑失败

- 显示 `message.error(res.msg || t('common.error'))`；
- `ModalForm.onFinish` 返回 `false`；
- 保持当前表单打开，便于用户修正后重试。

### 6.3 新增/编辑成功

- 显示成功提示；
- 调用 `actionRef.current?.reload()` 刷新弹框内字典数据表格；
- 返回 `true` 自动关闭对应表单。

### 6.4 删除成功

- 显示成功提示；
- 刷新弹框内字典数据表格；
- 不关闭字典数据主弹框，便于连续维护同一字典类型下的数据。

## 七、实现边界

本次改造仅限前端交互与结构重组，不包含以下内容：

- 不新增或修改后端接口；
- 不改变字典类型与字典数据的数据结构；
- 不调整权限模型；
- 不引入新的状态管理方案；
- 不将字典数据弹框改为抽屉或独立路由页。

这保证改造聚焦于用户提出的页面交互优化，避免范围膨胀。

## 九、与现有规范的一致性

本方案与项目规范保持一致：

- 使用 `ProTable` / `ModalForm` 作为中后台页面的优先组件；
- 不在页面主文件中继续堆叠多个职责，改为提取局部组件；
- 保持字典类型与字典数据写操作成功后通过 `actionRef.current?.reload()` 刷新；
- 不引入额外请求库、状态库或无必要的 UI 封装。

最终效果是：字典管理页聚焦在“字典类型列表”，字典数据改为按需弹出查看与维护，交互更直观，代码结构也更便于后续维护。
